# UI:三欄版面與共用行為

三欄結構、網址狀態、欄位儲存時機、寫入佇列與焦點遞補、中欄過場。**動到 state、effect、焦點或資料流前讀這一份。**

功能各自的行為另見 `docs/ui/checklist.md`、`docs/ui/recurrence.md`、`docs/ui/habits.md`。決策理由見 `docs/decisions.md` §4、§5。

## 三欄

| 欄 | 職責 |
|---|---|
| 分類欄 | 智慧檢視清單;決定第二欄顯示哪些任務 |
| 任務清單 | 頂端是新增列,下方是任務列;點任務列選取它 |
| 編輯欄 | 顯示被選取的任務,各欄位可編輯 |

本輪的智慧檢視只有查詢條件,沒有自訂清單表:今天、未來 7 天、全部未完成、已完成。另外有「習慣」(`view=habits`),中欄換成習慣清單、右欄換成習慣的編輯面板,見 `docs/ui/habits.md`。

**選取狀態放在網址。** `?view=today&task=123`。`view` 是分類欄選的檢視,`task` 是被選取的任務 id;沒有 `task` 時編輯欄顯示空狀態。`useSearchParams` 在 `ThreeColumnLayout` 讀一次往下傳,用 `router.replace` 寫。不要用元件內的 state 存這兩個值。

## 欄位儲存

**每個欄位各自儲存,各自送一次 PATCH。**

| 欄位 | 儲存時機 |
|---|---|
| 標題 | 失焦即存 |
| 描述 | 失焦即存 |
| 優先級 | 點選即存 |
| 截止日 | 選好按確定才存;與重複設定一起,在同一個日期選單裡按確定才存 |
| checklist 項目 | 勾選即存;文字失焦或 Enter 存;新增列按 Enter 送出;刪除不跳確認 |

**編輯中的輸入框不被重抓覆蓋。** 標題與描述在聚焦期間,值由該輸入框自己的 local state 持有;失焦後才跟隨伺服器資料。這是「畫面更新一律重新抓」的唯一例外,理由是慢網路下重抓回來的舊值會蓋掉使用者正在打的字。

**欄位被伺服器拒絕時保留輸入值。** 送出的值被擋下來時,輸入框留著使用者打的內容,不還原成伺服器的值;輸入框標示錯誤狀態,訊息畫在該欄位下方。使用者一修改該欄位就清掉錯誤。中欄任務列顯示的仍是伺服器的值。

**錯誤訊息的位置。** 欄位層級的錯誤畫在該欄位下方;其餘(404、500、網路失敗)顯示在中欄新增列下方。錯誤代碼在 `src/lib/errors.ts` 轉成中文。

描述是純文字,不做 Markdown 渲染。

## 掛載與對話框

**右欄的狀態生命週期綁在掛載上。** `TaskDetail` 以 `key={task.id}` 掛載,切換任務時欄位草稿、錯誤訊息、確認彈窗狀態隨卸載清除,不要另外寫 effect 逐一清。

**對話框一律經 `dialog.close()` 關閉。** 確定、清除、取消、Esc、背景點擊走同一條路徑:先 `close()`,再由 `<dialog>` 的 close 事件通知父層,並在 close 事件中明確把焦點移回觸發鈕;會卸載觸發鈕的動作(如確認刪除)除外。不要讓父層直接卸載開啟中的 `<dialog>`。

## 寫入佇列與焦點遞補

**任務寫入由 `ThreeColumnLayout` 排隊。** `mutate` 被呼叫的當下(事件處理中)記錄焦點所在的任務、它在中欄的索引、焦點在哪一類控制項(中欄勾選框、中欄的列、右欄),連同寫入一起排入佇列。重抓完成後,若該任務已不在目前視圖的清單裡、且焦點已掉到 body,焦點移到遞補列(下一列 → 上一列 → 中欄容器);原本在勾選框就移到遞補列的勾選框,其他情況移到遞補列的標題。刪除、勾完成、改欄位離開篩選共用這一套,`handleDelete` 不自己處理焦點。任務仍在視圖裡時不動焦點。

## 中欄過場

**中欄任務列進出有過場。** 列離開清單(勾完成、改欄位離開篩選、刪除)時淡出並收起高度,新進入的列淡入;時長與曲線用 `globals.css` 的 `--motion-duration`、`--motion-easing`。`TaskList` 比對前後兩次畫出的列(看 id 序列,不看陣列參考),把離開的列以退場列(`key` 前綴 `exiting-`)畫在原位置,收完高度後移除;換檢視、首次載入、`prefers-reduced-motion: reduce` 時不產生退場列,直接切換。退場列不帶 `data-task-id` 且 `inert`:遞補焦點的計算看不到它,焦點也落不到它身上。動畫不擋寫入,連續操作時前一輪的退場列直接被新畫面取代。

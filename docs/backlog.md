# Backlog

還沒做的事,以及已知但暫時接受的問題。

**這份是清單,不是規格。** 動手做某一項之前,先把它的規則寫進 `CLAUDE.md` 或對應的 `docs/` 檔,再實作;決策理由寫進 `docs/decisions.md`。

`CLAUDE.md` 只保留「之後才做」的項目名稱,細節在這裡。

## 開發順序

1. checklist(已完成)
2. 重複任務、習慣(資料層與 API 已完成;重複任務的 UI 已完成,習慣 UI 為 H2)
3. 版面 session:三欄可拖拉欄寬、右欄先縮後隱藏、抽屜覆蓋
4. 中欄的分組、排序、置頂(已完成,提前到版面 session 之前;決策見 `docs/decisions.md` §6d)
5. 目標最小實體(決策見 `docs/decisions.md` §6e)
6. 右欄的分類指派(需要 `list` 表與 `task.listId`)
7. 標籤(多對多,牽動左欄篩選與分組)

排程視圖(C1–C3,`docs/decisions.md` §6c)與習慣回顧視圖(H3)不在這條主線上,做完版面 session 後再決定插在哪裡。

## 已知問題

| 問題 | 回頭點 |
|---|---|
| 初次載入失敗與寫入失敗顯示在同一個位置(新增列下方),看不出是哪一種來源 | 與錯誤訊息的位置一起檢討 |
| `CategoryColumn` 的「今天」在伺服器端與瀏覽器端可能不一致(`/` 是靜態頁面,日期在建置時固定),會造成 hydration 錯誤與整棵子樹重新產生 | 與 `views.ts` 的日期篩選、相對日期顯示屬於同一類問題,待統一處理 |
| `task.parentTaskId` 的外鍵沒有指定 `onDelete`,且連線開啟 `foreign_keys = ON`,刪除有子任務的父任務會失敗(500) | 做子任務時必須先決定刪除行為 |
| 觸控裝置沒有 hover,checklist 的刪除鈕不會出現 | 手機開始使用時 |
| 色盲使用者無法區分任務列的優先級顏色(純顏色,無形狀差異) | 個人工具,刻意接受;這套元件若進共用設計系統再處理 |

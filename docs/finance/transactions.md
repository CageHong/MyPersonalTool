# 交易清單

交易清單的查詢語意。程式在 `src/modules/finance/server/ledger/list.ts`(`listTransactions`),
API 是 `GET /api/finance/transactions`,畫面是 `/finance/transactions`。篩選規則只在 `listTransactions` 定義;
之後的報表、匯出、批量編輯要「符合某組條件的交易」時呼叫它,不另寫一份。

## 網址參數

參數名在 `src/modules/finance/lib/transactions.ts` 定義(畫面寫網址、route 解析都用它)。

| 參數 | 意思 |
|---|---|
| `from`、`to` | 日期範圍 `YYYY-MM-DD`,含頭尾兩天;以 UTC 切日(跟 `ledger/balances.ts` 相同) |
| `account` | 有任何分錄記在這個資產或負債帳戶 |
| `category` | 有任何分錄記在這個分類;上層分類包含它的子分類 |
| `tag` | 交易掛了這個標籤 |
| `payee` | 交易的對象 |
| `kind` | 交易類型(見下) |
| `uncategorized=1` | 有分錄記在「未分類」或「未分類收入」 |
| `q` | 收款人名稱、收款人別名、備註、分錄備註部分相符;不分大小寫只對英文字母;`%`、`_` 是一般字元;最長 100 字 |
| `order` | `desc`(預設,由新到舊)或 `asc` |
| `cursor` | 上一頁回傳的 `nextCursor` |
| `limit` | 每頁筆數,1–200,預設 100 |

條件之間是「而且」。不合法的參數回 400(`VALIDATION_FAILED`,`fields` 依參數名)。

已知的不一致:日期篩選以 UTC 切日,畫面顯示的是瀏覽器時區的日期。在 UTC 以東的時區,深夜的交易可能顯示在隔天、
卻要用前一天的日期篩到。

## 分頁(keyset)

依 `(occurred_at, id)` 排序,下一頁從上一頁最後一筆之後開始。`cursor` 是那一筆的 `(occurred_at, id)`
編成的不透明字串。兩次請求之間帳本新增或刪除交易,不會讓列重複或遺漏(offset 分頁會)。
沒有總筆數、不能跳頁;畫面捲到底自動載入下一頁。

`occurred_at` 以字串比較。ledger 目前接受 `Z` 與 `+00:00` 兩種結尾和小數秒;混用時只有同一秒內的順序可能不直覺,
分頁仍然正確(排序與 cursor 用同一種比較)。

## 交易類型

不存在資料庫裡,由分錄涉及的帳戶推導,依序判斷、先符合的優先:

1. 有分錄在系統帳戶「換匯」→ `exchange` 換匯
2. 有分錄在其他權益帳戶(期初餘額)→ `opening` 期初餘額
3. 有手續費以外的支出分類,也有收入分類 → `mixed` 支出與收入
4. 有手續費以外的支出分類 → `expense` 支出(退款也是支出,金額為正)
5. 有收入分類 → `income` 收入
6. 只有手續費,而且只動到一個資產 / 負債帳戶 → `expense` 支出(單純被收手續費)
7. 其餘(只有資產、負債,或只有手續費但動到兩個以上的資產 / 負債帳戶)→ `transfer` 轉帳

手續費不決定類型:換匯、支出、轉帳都可能帶手續費。帶手續費的轉帳(A −101、B +100、手續費 +1)是轉帳,不是支出。

## 每一列的欄位

- **分類**:分類側(支出、收入帳戶)的分錄,依分錄順序、不重複;子分類帶上層名稱。轉帳、換匯、期初餘額的分類欄顯示類型。
- **帳戶側(`legs`)**:資產、負債帳戶的分錄,同一個帳戶合併成一筆、合計為零的不列。是錢實際的進出:
  支出為負、收入為正;轉帳、換匯有兩筆;付保證金這類「一部分是支出、一部分轉到另一個資產帳戶」的也有兩筆。
- **折合金額(`displayAmount`)**:分類側分錄加總後取負號(支出為負、收入與退款為正),
  用交易當天的匯率換成顯示幣別(`finance_settings.display_currency`),多種幣別先換算再加總、最後取整數。
  是損益,不是錢的進出:付 1,000、其中 400 是保證金時,帳戶側是 −1,000,折合金額是 −600。
  支出與收入(`mixed`)是兩邊相抵後的淨額。轉帳、換匯、期初餘額是 `null`,帶手續費的也一樣(手續費看分錄);
  缺匯率時也是 `null`。
- **分錄(`postings`)**:全部分錄,依 `sort_order`。
- **`updatedAt`**:最後修改的時間;編輯時原樣帶回去,用來判斷資料是不是舊的。

## 編輯(單筆)

程式在 `src/modules/finance/server/ledger/transactions.ts`(`updateTransaction`),請求的形狀與協定層的解析在
`src/modules/finance/lib/edit.ts`。API:`GET /api/finance/transactions/<id>`(一列,形狀同清單)、
`PATCH /api/finance/transactions/<id>`(成功時回傳改好的那一列)、`DELETE /api/finance/transactions/<id>?expectedUpdatedAt=…`(204)。
畫面:清單網址加 `?edit=<id>` 打開右欄;換篩選條件時保留,關閉時拿掉。右欄的「編輯分錄…」打開分錄對話框(送 `postings`),
「刪除交易」先跳確認。右欄有還沒儲存的修改時,這兩個按鈕停用。

`PATCH` 只放要改的欄位:

| 欄位 | 規則 |
|---|---|
| `expectedUpdatedAt` | 必填。打開時拿到的 `updatedAt`;跟資料庫不同(別的分頁或匯入改過)回 400 `expectedUpdatedAt: stale`,什麼都不寫 |
| `occurredAt` | UTC 的 ISO 8601,存成 `YYYY-MM-DDTHH:MM:SS+00:00`。畫面用瀏覽器時區輸入日期與時刻(到秒) |
| `note` | 去頭尾空白;空字串 = 清空;最長 1000 字 |
| `payee` | `{ id }` 選既有的;`{ name }` 先比對別名、再找同名的,都沒有才新增收款人(並建立別名);`null` 清空 |
| `categories` | `[{ postingId, accountId }]`:把那條分錄換到另一個分類,金額不變。分錄必須是這筆交易的支出 / 收入分錄;只能換成同類型的分類;手續費不能換進換出;封存的分類不能選(原本就是它的可以留著) |
| `postings` | `[{ accountId, amount, currency, memo }]`:整組替換分錄(拆帳、改成轉帳、收回保證金或代墊、改金額)。檢查跟新增交易相同:至少兩條、金額是非零整數、帳戶與幣別存在、有固定幣別的帳戶幣別要一致、每個幣別加總為零。不能跟 `categories` 一起給。內容跟現在完全一樣時不動 |
| `tags` | `{ ids, newNames }`:改完後的完整標籤。新名稱去頭尾空白,同名的已經存在就用它,沒有才新增(一般標籤,沒有日期範圍) |

- 全部在同一個 DB transaction;任何一項不合法回 400、整筆不寫入(新建的收款人與標籤也不留下)。
- 分類或分錄真的換了才改 `category_source`:有使用者選的分類就是 `manual`(對象歷史會採用它);沒有分類(變成轉帳)或全部是「未分類」/「未分類收入」時是 `null`。手續費不算分類。
- `updated_at` 存到毫秒(同一秒內連續編輯也分得出版本)。
- 分錄對話框:金額分借、貸兩欄,下方即時顯示各幣別的差額;每一行可以「補差額」(這一行吸收自己幣別的差額)、「拆開」(下面插一行同帳戶、同幣別、沒有金額的)。匯入的交易改了資產 / 負債那一側的金額時會提醒:下次匯入同一份檔案會列為「金額不同」(只報告、不改回來)。
- **刪除**:分錄與標籤一起刪。有來源 ID 的(匯入的)把 ID 與刪除當時的內容(JSON 快照)記進 `finance_deleted_external_ids`,之後匯入同一份檔案時列為「刪掉過」、不加回來。同樣檢查 `expectedUpdatedAt`。
- 第一次編輯(含刪除)時一起寫入 `finance_settings` 的 `v2_retired_at`;之後 `finance:import-v2` 拒絕執行(它每次從空的資料庫重建,會洗掉畫面上的修改)。
- 改了對象不會重新分類。改完之後不符合目前篩選條件的列先留在畫面上,重新整理或換條件時才消失。
